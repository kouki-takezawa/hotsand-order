# Hotsand Order

🔗 **本番URL**: [https://hotsand-order.vercel.app](https://hotsand-order.vercel.app)

QRコードから注文できる、ホットサンド専門店向けの注文・厨房管理システム。Next.js (App Router) + Prisma Postgres + NextAuth (Auth.js) で構築。

このREADMEは、実装済みの仕様をひととおり日本語でまとめたものです。コードの正としての役割は各ファイルのコメントが担い、ここでは「何ができるか」の全体像を把握できるようにしています。

## 概要

### これは何か

**Hotsand Order** は、イートインの席を持たないホットサンド専門店（テイクアウト・提携店舗への軽食提供など）向けに作られた、**QRコード注文＋厨房管理システム**です。客は自分のスマートフォンでQRコードを読み取るだけでメニューを見て注文でき、店舗スタッフは注文の受付から調理・受け渡しまでを管理画面上で一元管理できます。

### 目的・背景

小規模な飲食店・軽食スタンドでは、次のような課題がよくあります。

- 電話や口頭での注文はミスや聞き漏らしが起きやすく、繁忙時にはさばききれない。
- 座席を持たない・複数拠点にQRを掲示するような運用形態には、既存の「テーブルオーダー」型システムが合わない。
- 注文状況（今どの注文が調理中で、どれが受け渡し待ちか）を厨房とレジ・カウンターでリアルタイムに共有したい。
- メニュー変更・値上げのたびにエンジニアへ依頼して再デプロイするのは非効率。

Hotsand Orderは、これらを解決するために「客はQRを読むだけ・アカウント登録不要」「店舗側はブラウザだけで注文管理・メニュー変更が完結」というシンプルな構成を目指して作られています。会計・決済そのものは対象外とし、あくまで**注文の受付〜調理〜受け渡しのオペレーション管理**に特化しています。

### 対象ユーザー

- **客（エンドユーザー）**: アカウント登録不要。QRコードを読み取って注文し、注文番号でステータスを確認する。
- **店舗スタッフ**: ログインして注文管理・売上確認・メニューやQRコードの設定を行う。

### 注文フローの仕組み

1. 店舗が「設置場所（提携店舗・拠点）」ごと、または共通のQRコードを発行し、店頭や拠点に掲示する。
2. 客がQRコードを読み取ると、ログイン不要で注文画面（`/order`）が開く。
3. メニューから商品を選んでカートに入れ、「注文する」を押すとサーバーに送信され、JST日付ごとの通し番号（例: `#12`）が発行される。
4. 店舗スタッフは注文管理画面（`/staff/orders`）で、届いた注文を「受付→調理中→受渡済み」の順にステータス変更していく（いつでも取消・差し戻しも可能）。
5. 客側の画面にはリアルタイムで注文ステータスが反映され、任意でWeb Pushの通知も受け取れる。
6. 実際の会計（金額の授受）は別のレジ・POSで行う前提で、本システムでは扱わない。

### chil-terrace-orderとの違い

本リポジトリは [kouki-takezawa/chil-terrace-order](https://github.com/kouki-takezawa/chil-terrace-order)（イートイン型カフェ向けの注文・予約・シフト管理システム）をベースに、ホットサンド専門店向けに作り直したものです。主な違いは次のとおりです。

- イートイン運用を前提とした**座席予約表・スタッフのシフト表機能を削除**し、テイクアウト・複数拠点QR運用に特化したスコープに絞り込んだ。
- 座席の概念を廃し、代わりに「設置場所（Location）」という、QRコードの掲示場所を表すタグ概念を導入した。
- メニューに残数管理（在庫が0で自動販売停止）や価格改定予約など、軽食スタンド運用向けの機能を追加している。

### 主な機能

- **客側: QRコード注文**
  - ログイン・会員登録不要で、QRコードを読み取るだけで注文可能
  - カテゴリ別のメニュー表示、数量指定、カート機能
  - 注文するたびに番号発行、待ち件数・待ち時間の目安表示
  - 注文履歴の自動保存（`localStorage`）・ステータスのリアルタイム反映
  - Web Pushによる注文ステータス変更通知（対応端末のみ・任意）
  - アレルギー品目による商品の絞り込み表示
- **店舗側: 管理画面（要ログイン）**
  - 注文管理ボード（受付／調理中／受渡済みのステータス管理、取消）
  - 売上ダッシュボード（本日の集計、時間帯別・昼夜別グラフ）
  - 注文分析（人気メニューランキング、カテゴリー別売上構成、設置場所別集計）
  - 期間分析（日別売上推移、CSV・Excelエクスポート）
  - メニュー管理（カテゴリー・商品の追加編集、セットメニュー登録、残数管理、価格改定予約）
  - 設置場所・QRコード管理（拠点ごとの発行、受付の一時停止/再開、印刷用レイアウト）
  - スタッフアカウント管理・招待コードによる新規登録
- **共通基盤**
  - 全店舗一時停止フラグによる臨時休業対応
  - 店舗名・Wi-Fi案内など、再デプロイ不要でDBから変更できる設定項目

## 全体構成

- ルートURL（`/`）は常に `/staff/login` にリダイレクトされる。客はQRコードから直接 `/order` にアクセスするため、ルートURLを客向けに使うことはない。
- 客側の画面（`/order`）はログイン不要。誰でもアクセスでき、アカウント作成は一切不要。
- 店舗側の画面（`/staff/*`）はログイン必須。未ログインでアクセスすると `/staff/login` にリダイレクトされる（`src/proxy.ts` によるガード）。各APIルートも個別にセッションを検証している（多層防御）。
- 店舗名・メニュー・スタッフアカウントは、すべてDBで管理され、設定画面からいつでも変更できる。**再デプロイは不要。**

## 運用方式（受け取り・配達）

このアプリはイートインの席を持たない前提で作られている。同じQRコードを複数の提携店舗・拠点に掲示し、客がそこから注文する運用を想定している。

- QRコードは「設置場所」（`Location`）ごとに1枚発行できる（設定＞設置場所／QRコード）。座席の概念は持たず、あくまで「どのQR経由の注文か」を記録するためのタグ。特定の設置場所に紐付けない共通QRも常に使える。
- 客がQRを読み取ると `/order` が開き、注文するたびに「本日の注文番号」（`OrderCounter` によるJST日付ごとの連番、日が変わると1から採番し直す）が発行される。
- 設置場所ごと、または全店舗一括で、注文受付を一時停止できる（設定＞設置場所／一般）。停止中はそのQRを読み取っても注文画面を開けず、案内画面が表示される。
- **会計・決済機能はこのアプリでは持たない。** 会計は別のレジ／POSシステムで行う前提。スタッフは注文のステータス（受付／調理中／受渡済み）のみを管理する。
- 実際の受け渡し方法（店頭で客が受け取るか、店舗まで配達するか）はオペレーション側の判断であり、アプリ側で区別・記録はしない。
- 売上ダッシュボードの金額は「受け渡し済み（目安）」「対応待ち（目安）」として表示され、実際の会計金額とは独立している旨を明記している。

## 客側の機能

### 注文画面（`/order`）

- カテゴリタブ（ホットサンド・サイド・セット・ドリンクなど、設定で自由に追加・変更可）で商品を切り替え。
- 各商品に `+` / `−` ボタンで数量を指定し、カートに追加。
- 下部固定バーに合計点数・合計金額・「注文する」ボタン。
- 注文すると即座にサーバーへ送信され、店舗側の注文管理画面にリアルタイム（数秒間隔のポーリング）で反映される。

### 注文履歴・合計（客側）

- 注文するたびに大きく番号（例: `#12`）が表示され、その注文の内容と合計、現在のステータスがリアルタイムに更新される。「追加で注文する」でメニューに戻って続けて注文でき、同じブラウザで行った過去の注文はすべて記憶される（`localStorage`）。「これまでの注文履歴・合計」から、これまでの全注文とその合計金額を一覧できる。
- ページを閉じて再度QRを読み取っても、直近の注文状況・履歴は自動的に復元される。
- 番号発行画面には「あと何件先に並んでいるか」と受け取りまでの目安時間（受付・調理中の件数から単純計算、1件あたり4分換算）を表示する。
- 「🔔 通知を受け取る」からWeb Pushの許可を求め、許可するとその注文のステータスが変わる（調理開始・受渡可能・取消）たびにブラウザ通知が届く。対応していない端末・拒否した場合は画面を開いたまま待つ従来の挙動になる。
- メニュー画面で原材料アレルギーを指定して、該当する商品を一時的に非表示にできる（「アレルギーで絞り込む」）。

## 店舗側の機能

すべて `/staff/login` からログイン後にアクセスする。ログイン画面には新規登録（アカウント作成）フォームもあり、招待コード・名前・メール・8文字以上のパスワードを入力するとその場でアカウントが作られ、自動的にログインされる。

新規登録には招待コードが必須（設定＞招待コードから既存スタッフが発行する）。コードは1回使うと失効し、任意で有効期限も設定できる。招待コード付きのURL（`/staff/login?invite=コード`）を共有すれば、リンクを開くだけで新規登録フォームが開きコードも自動入力される。

### 注文管理（`/staff/orders`）

- 進行中の注文（受付・調理中）が番号順にフラットに並ぶ。受渡済みになった注文はボードから自動的に消える。
- 各注文のステータスは「受付／調理中／受渡済み」のピルボタンで**どれでも自由にタップして変更できる**。一方向にしか進めない仕様ではないため、ミスタップしても正しい状態に戻せる。「取消」でいつでもキャンセルできる。
- どの設置場所のQRから来た注文かがカードにタグ表示される（共通QRの場合はタグなし）。
- 6秒間隔で自動的に最新状態へ更新される（ポーリング）。

### 売上ダッシュボード（`/staff/dashboard`）

- 本日（JST基準）の集計をリアルタイムに表示。
- 受け渡し済み（目安）／対応待ち（目安）／本日の注文件数／客単価／受け渡し件数／取消件数。
- 時間帯別売上（1時間ごとの棒グラフ）と、昼夜の内訳円グラフ。

### 注文分析（`/staff/analytics`）

- 期間（本日／過去7日間／過去30日間）を切り替えて、人気メニューランキング（販売数トップ10）とカテゴリー別売上構成（円グラフ）を確認できる。
- 設置場所別の注文件数・売上も一覧で確認できる（CSV・Excelエクスポートにも含まれる）。
- 注文件数・期間売上・平均注文点数のサマリも表示。

### 期間分析（`/staff/reports`）

- 期間（過去7日／30日／90日）を切り替えて、日別売上の推移を棒グラフで確認できる。
- 期間合計売上・期間注文件数・客単価（期間平均）・取消件数のサマリも表示。

### 設定（`/staff/settings/*`）

タブ構成: 一般 / メニュー / 設置場所 / QRコード / アカウント / 招待コード

- **一般**: 店舗名、Wi-Fi案内（任意・客側の注文画面に表示）、**全店舗の注文受付を一時停止するチェックボックス**（臨時休業・仕込み切れなどに使う）。
- **メニュー**: カテゴリーの追加・名称変更・削除（商品が残っているカテゴリーは削除不可）。商品の追加・編集（名前・価格・説明・おすすめフラグ・販売中フラグ・アレルギー表示・商品写真URL・**残数管理**・価格改定の予約適用）・削除（注文履歴がある商品は削除不可。販売停止フラグで対応する）。**セットメニューも通常の商品として自由に追加できる**（例:「ハム&チーズ+ポテト+ドリンクセット」を1つの商品として登録）。**残数管理**を設定すると、注文が入るたびに自動で1減り、0になった時点で自動的に販売停止になる（取消された場合は在庫が戻る）。価格改定を予約している商品には「📅 ○/○から¥Xに変更予定」の見出しが付き、その場で予約を取り消せる。印刷用の一覧表示、CSV・Excelでのダウンロードにも対応。
- **設置場所**: QRコードを設置する提携店舗・拠点の追加・名称変更・削除（注文履歴がある設置場所は削除不可）、および設置場所ごとの受付一時停止/再開。
- **QRコード**: 設置場所ごとのQRコードに加えて、設置場所に紐付けない共通QRを表示。「印刷する」ボタンで、各拠点への掲示用に大きく印刷できるレイアウトになる（印刷ダイアログで「PDFに保存」を選べば、まとめてPDF化もできる）。QRのURLは環境変数 `NEXT_PUBLIC_APP_URL`（未設定時はリクエストヘッダーから推測）を基点にしており、Vercelのデプロイ固有URLなどではなく本番の正式ドメインを指す。
- **アカウント**: ログインアカウントの一覧、追加（名前・メール・8文字以上のパスワード）、削除（最後の1件は削除不可）、パスワード再設定。
- **招待コード**: 新規登録に必要な招待コードの発行・無効化。コードは1回使うと自動的に失効し、任意で有効期限（日数）も設定できる。「コード付きURL（`/staff/login?invite=コード`）」としても共有できる。

## 認証・アカウント

- NextAuth (Auth.js) の Credentials プロバイダ + JWTセッションを使用。
- パスワードは bcrypt でハッシュ化して `StaffUser.passwordHash` に保存。
- ログイン画面から新規登録が可能（招待コードが必須。設定＞招待コードから発行する）。
- 設定＞アカウントから、既存メンバーがアカウントを追加・削除・パスワード再設定できる。
- 初回デプロイ時（アカウントが1件も無い場合のみ）、環境変数 `STAFF_EMAIL` / `STAFF_PASSWORD` から最初のアカウントが自動作成される（`prisma/seed.ts`）。

## データモデル

主要なテーブル（`prisma/schema.prisma` 参照）:

| モデル | 役割 |
|---|---|
| `StaffUser` | 店舗スタッフのログインアカウント |
| `StaffInvite` | 新規登録に必要な招待コード |
| `Settings` | 店舗名・全店舗一時停止フラグなどを1行だけ持つシングルトン |
| `Category` / `MenuItem` | メニューのカテゴリーと商品（セットメニューも通常の商品として登録。アレルギー表示・商品写真URL・残数管理・価格改定予約を含む） |
| `Location` | QRコードを設置する提携店舗・拠点（受付一時停止フラグを含む） |
| `OrderCounter` | JST日付ごとの通し番号カウンタ |
| `Order` / `OrderItem` | 注文とその明細（明細は注文時点の商品名・単価をスナップショットとして持つ。Orderは設置場所ID・Web Push購読情報も保持） |

`Order.status`（pending → preparing → served / cancelled、いつでも取消しうる）が状態管理の中心。マイグレーションファイルは持たず、デプロイのたびに `prisma db push` でスキーマをそのまま反映する運用。

## 環境変数

`.env.example` を参照。主なもの:

- `DATABASE_URL` ほか — Postgres接続文字列（`src/lib/env.ts` が複数の命名パターンにフォールバック対応）
- `AUTH_SECRET` — NextAuthのセッション暗号化キー
- `STAFF_EMAIL` / `STAFF_PASSWORD` — 初回デプロイ時（アカウントが1件も無いときだけ）に作成される最初のスタッフアカウント
- `NEXT_PUBLIC_APP_URL` — QRコードに埋め込む絶対URLの基点（本番の正式ドメインを指定）
- `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `VAPID_SUBJECT` — 注文ステータス変化のWeb Push通知用（`npx web-push generate-vapid-keys` で生成）。未設定でも通知機能が無効になるだけでアプリ全体は動作する。

## セットアップ

```bash

```


### メニューを一括更新する

`prisma/menu-data.ts` に現在のメニュー内容が定義されている。

- **新規環境**（DBにカテゴリーが1件も無い場合）: 上記の `npm run db:seed` で自動的にこの内容が入る。
- **すでに旧メニューが投入済みの環境**（本番など）: `npm run db:reset-menu` を実行すると、既存メニューを `prisma/menu-data.ts` の内容に一括更新する。注文履歴が無い商品は削除、注文履歴がある商品は削除できないため「販売停止」扱いにしたうえで、新メニューの内容を投入する（複数回実行しても安全）。実行前に `.env.local` の `DATABASE_URL` が対象の環境を指していることを確認すること。
- 日常的なメニュー追加・変更（新商品・セットメニューの追加など）は、コードを触らず設定＞メニュー画面から行う。

## デプロイ

Vercelに接続済み。`main` ブランチへのpushで自動デプロイされる。`vercel-build` スクリプトがデプロイの度に `prisma generate` → `prisma db push --accept-data-loss` → シード投入（データが無い部分のみ） → `next build` を実行する。

## 既知の制約・今後の余地

- 会計・決済処理そのものは実装していない（ステータスを「受渡済み」に進めるだけ）。
- 座席・卓の概念は持たない。イートイン運用が必要になった場合は別途設計が必要。
- メニュー画像のアップロードには対応していない。設定＞メニューで外部にホストされた画像のURLを指定する方式のみ。
- 予約表・シフト表機能は、ベースにした [chil-terrace-order](https://github.com/kouki-takezawa/chil-terrace-order) から意図的に削除している（本アプリのスコープ外）。
